tmDataQualityAnalyzer v3.5.1 - What's New
=================================

  Installing over v3.5.0 replaces it and keeps your settings files and
  window preferences. Choose the same "for all users" or "only for me" as
  you did for v3.5.0, so that it is replaced rather than installed beside.
  If you have a version older than v3.5.0 installed with its setup.exe,
  please read the v3.5.0 notes below.

  Changed:

  - Process Multiple Files says, before it starts, that it clears the plot
    first. Cancel in its progress window now stops the whole batch: the
    files already processed stay on the plot (and are exported, when you
    chose a folder), and the rest are skipped. It used to skip only the
    file being processed and go on with the next.

  Improved:

  - Export Data is about twice as fast on a large plot. The files it writes
    are the same.

  - A screen reader names each channel on the Receiver SNR tab of Customize
    View ("L of RCVR 3"), each receiver's box and its open/close button.
    The three receivers' channels used to sound alike.

  - The file pickers and tips name what the menu names (Import from CSV,
    Process Multiple Files, Save Template), and the Import tip says that it
    reads an exported CSV or an antenna's log and adds it to the plot.

  Fixed:

  - A recording opened after importing an antenna's log or an exported CSV
    is placed on the time axis by its clock, beside the log. It used to be
    placed decades later, which stretched the time axis over 56 years.

  - Zoom Back goes back to the view you had, after opening a recording that
    starts earlier than what the plot showed. It used to land off by the
    difference.

  - An imported CSV whose rows are not in time order is shown to its latest
    time instead of being cut short. A first time stamp just below zero no
    longer moves the next row to zero.

  - A CSV file that cannot be read (no longer there, or held open by another
    program) is reported as unreadable, with the reason, instead of as a
    file of the wrong layout.

  - The cursor's time label no longer shows a time such as 01:00:00.1000
    when the fraction of a second rounds up: it reads 01:00:01.000.

  - Clearing the plot while Configure Streams was open no longer leaves the
    recording named as a second file, without the plot's title. An error
    while showing a stream is reported in the log instead of closing the
    application.

  - The user manual's description of Plot File, the CSV's file prefix, the
    right-click menu and the keyboard (Backspace for Zoom Back) says what
    the application does.

  Everything else is as in v3.5.0, below.


tmDataQualityAnalyzer v3.5.0 - What's New
=================================

  Installing: this version comes as a Windows Installer package (.msi) in
  place of the old setup.exe. If you installed an earlier version with its
  setup.exe, uninstall it first (Settings > Apps > tmDataQualityAnalyzer >
  Uninstall): the new installer will not install beside it. Your settings
  files are not removed by the uninstall. The installer asks whether to
  install for all users (administrator rights needed) or only for you (no
  administrator rights needed). The portable ZIP is unchanged.

  New:

  - Nothing replaces the plot any more. Opening a recording adds it beside
    whatever the plot shows, and so does importing a CSV file, dropping a
    file on the window or choosing one under Recent Files. Each keeps its
    own name in the legend, in Plot File and in Remove File.

  - Clear Plot..., on the plot's right-click menu, empties the plot, with its
    title and view, after asking once. It is how you start again.

  - Remove File..., on the plot's right-click menu, takes one recording, one
    file of a batch or one imported CSV file out of the plot and keeps the
    rest. What is removed is no longer exported. If the earliest recording
    is removed, the time axis starts again from the earliest one left.

  - Importing a CSV no longer asks what kind of file it is: the application
    recognises its own exports and AV phased array antenna logs by
    themselves. A file that is neither is refused with a message, and the
    plot is left as it was.

  - Extract Calibration lets you choose the PCM channel and the time channel
    of the calibration recording. A calibration recorded on a different
    channel from the stream you are setting up can now be used. The lists
    start on the stream's own channels when the recording has them.

  Changed:

  - The plot has two legends: Framesync Series at the top left and SNR
    Series at the top right.

  - Frame Sync Lock and Receiver SNR are told apart by their lines and
    colours: Frame Sync Lock (and missed frames) is always drawn solid, and
    Receiver SNR, from a recording or an antenna's log, always dotted, with
    closer dots than before. Both use the same 15 colours, Receiver SNR from
    the other end, so a stream's lock and its SNR are not the same colour.
    Within a receiver the combined channel is the full colour and the other
    two lighter shades of it, as before.

  - File > Add Recording... is gone: File > Open... does what it did.

  - The application has a new icon.

  - The installer offers the application for .ch10 files under "Open with"
    rather than making it their default, so Windows asks once which
    application to use, and an uninstall never takes .ch10 away from another
    application. Administrators can deploy it silently (Group Policy, SCCM,
    Intune).

  Improved:

  - Colours you set in Customize View, or that a template set, are kept when
    another recording, an antenna's log or a batch's next file is added. They
    used to go back to the defaults.

  - With more than one recording on the plot, Customize View lists each
    recording's streams separately, named for their recording.

  - A recording whose TMATS gives a stream no bit rate is refused with a
    message asking for that stream's Data Rate; entering it lets the stream
    run. It used to fail with a message blaming the time channel.

  Fixed:

  - A corrupt recording whose packet claims more data than it holds is now
    stopped with a message saying so, instead of risking a crash.

  - An unexpected error inside processing stops that run with a message,
    and the application stays open. It could close the application.

  - Typing a clip time in Extract Calibration no longer starts an extraction
    on every key press; it extracts once you stop typing.

  - Process Multiple Files gives files whose names start the same way (such
    as 2024.11.05_run1 and 2024.11.05_run2) separate exports, instead of
    writing both to the same file.

  - A CSV file given on the command line is imported, as it is when dropped
    on the window, instead of being opened as a recording.

tmDataQualityAnalyzer v3.4.0 - What's New
=================================

  Upgrading from v3.0.0, v3.1.0, v3.2.0, v3.3.0 or v3.3.1 keeps everything:
  your settings files and your window preferences. Upgrading from v2.x:
  please read the v3.1.0 notes below about your window preferences.

  Changed:

  - Export Data writes each column on the clock, rounded to its own sample
    rate. A recording whose channels each report once a second now exports
    one row a second, with every channel's cell filled, where it used to
    export four to seven rows a second, each holding one channel's value.
    Exact times are no longer written: a sample is placed at most half a
    sample period from where it fell. A column with no steady rate is still
    written to the millisecond. If something reads your exported files by
    row, expect fewer, fuller rows.

  Improved:

  - The application starts about twice as fast: its window is up in about
    0.4 seconds instead of 0.7 seconds. The download is larger as a result
    (the installer is about 46 MB).

  - The window, its dialogs and the progress window follow the light or dark
    theme in their title bars on Windows 10 as well as Windows 11.

  - A screen reader can say what every text box, list, button and switch is
    for: each has a name now, in the dialogs and in the title bar.

  - Wording is the same everywhere: Missed Frames, Export, Apply Calibration,
    Process Multiple Files and Customize View name the same thing in the
    menu, in the window's title and in the manual.

  - If the application closes on an unexpected error, it saves a report and
    tells you where it is, so you can send it with a note of what you were
    doing. The reports are in %APPDATA%\tmDataQualityAnalyzer\crash-reports\
    (beside the executable for a portable copy).

  - The cursor's readout on a plot imported from a CSV file whose times are
    not in order names the nearest sample.

  Fixed:

  - Select None on the Receiver SNR tab of Customize View clears every
    receiver in one press. It used to check them all, and needed a second
    press.

  - A recording whose time channel jumps years ahead (a corrupt time stamp)
    no longer makes a stream write millions of empty rows and run for
    minutes. That stream stops with an error saying where the time jumped.

  - A CSV column whose samples fall exactly half a period off the grid no
    longer loses a sample to rounding.

tmDataQualityAnalyzer v3.3.0 - What's New
=================================

  New:

  - Import a phased array antenna's SNR log. Import/Export > Import from
    CSV..., dragging a .csv file onto the window, or the Recent Files list
    now asks what the file is: a CSV this application exported (Standalone
    Telemetry Receivers) or a log written by an AV Inc. Phased Array Antenna.
    The antenna's log is drawn with one line for each stream and
    polarization (H, V and C), on the Receiver SNR axis, and is placed on the
    time axis by its clock. Imported while a recording is shown, it joins the
    plot as a recording of its own, so the two can be compared. At first only
    each stream's combined (C) line is shown; the rest are a click away in
    Customize View. The log is never exported as data, and Export Data is
    unavailable on a plot that holds nothing else.

  - Receiver SNR is drawn in 15 hues, one for each stream: the first 15
    streams as solid lines and the next 15 dotted, in the same hues. The
    combined channel of a stream is its strongest line and the only one shown
    at first.

  Improved:

  - The plot's Y axes are ticked at round values (0, 200, 400 ... rather than
    231, 462, 693 ...).

  - The legend sits beside the right axis's labels instead of over them when
    Receiver SNR is shown.

  - A recording whose name has an underscore, such as prn_testfile, is listed
    under its own name in the menu; the underscore used to be dropped.

  - The user manual describes the antenna log, and its figures were checked
    one by one: the names in them are the ones the application produces, and
    the text and the pictures tell the same story.


tmDataQualityAnalyzer v3.2.0 - What's New
=================================

  Upgrading from v3.0.0 or v3.1.0 keeps everything: your settings files and
  your window preferences. Upgrading from v2.x: please read the v3.1.0 notes
  below about your window preferences.

  New:

  - A status bar along the foot of the window says, in one short sentence,
    what the application is doing or has just done. It stays visible when the
    log is hidden.

  - The menu behind the three-line button is four submenus: File,
    Import/Export, Settings and Help. The light and dark theme are two
    entries of their own, with the one in use ticked. Help opens the User
    Manual, and Process Multiple Files... and Save Template... are named as
    the windows they open.

  Improved:

  - Processing is much faster. On a high-rate stream the frame sync scan now
    takes about a seventh of the time: a 20 Mbps channel of a 640 MB
    recording went from 11.6 seconds to 1.6. The answers are unchanged: every
    exported file for every recording we hold came out byte for byte the
    same as before.

  - A plot with a lot of data stays responsive while you pan and zoom it, with
    the mouse wheel, by dragging, or with the keys. The full picture is drawn
    when you let go.

  - Export no longer freezes the window while the data is written; a large
    recording used to leave it unresponsive for a second or more.

  - Numbers in the stream settings, the Receiver SNR dialog, Extract
    Calibration and the plot's prompts are typed into plain boxes, with no
    up and down arrows. A box refuses what is not a number.

  - A new look, taken from Visual Studio Code's Dark Modern and Light Modern
    themes: panes sit side by side separated by thin lines, the title bar is
    a dark grey, and the text is a little smaller (13 pixels). The dialogs share one layout with
    their buttons in the same place, and settings that are on or off are
    switches.

  - The window opens at 1920 x 1080, with the empty chart already showing its
    grid, and the divider between the log and the chart can be found and
    dragged.

  - The yellow Receiver SNR lines and their legend swatches are easier to see
    on the light theme.

  - The plot is drawn correctly on displays scaled above 100 percent.

  Fixed:

  - Receiver SNR values could be read from the wrong bit in the rare frames
    where data happened to look like the sync pattern while the stream was
    locked: about one frame in 65,536 with a sparse mask, far fewer with a
    full 32-bit pattern. Frame Sync Lock results were not affected.

  - If the shipped default receiver parameters file cannot be used, Extract
    Calibration now falls back the same way processing does and says so,
    rather than failing.

  - A drag on the plot that loses the mouse no longer carries on panning with
    no button held, and dropping a file on the window while a recording is
    being processed no longer shows a drop it would ignore.

  - If Extract Calibration cannot hand back its result, it says so instead of
    leaving "Processing calibration file..." on the screen.

tmDataQualityAnalyzer v3.1.0 - What's New
=================================

  Upgrading from v2.x - please read:

  - Your window preferences now start fresh. v3.0.0 brought over the
    preferences v2.x kept (the theme, whether the log sidebar and the legend
    are shown, your recent files, and the folders you last opened files
    from); v3.1.0 no longer does, and starts with the defaults instead. Your
    settings files - frame sync patterns, receiver parameter files and
    calibration step files - are kept, exactly as before.

    To keep your v2.x preferences, install v3.0.0 first and start it once
    (it brings them over), then install v3.1.0.

  - Upgrading from v3.0.0 keeps everything.

  Improved:

  - The application has its own icon again: in the title bar, the taskbar,
    Alt+Tab, Explorer and the Start menu. v3.0.0 showed a generic one.

  - The plot's single-key shortcuts - L, V, R, Backspace, Home, the arrow
    keys, + and - - now act only when pressed on their own. Ctrl+R or Ctrl+L
    no longer reset the view or hide the legend by accident. + still works
    with Shift, as most keyboards type it, and the keypad's + and - still
    zoom.

  - The user manual's pictures show this version. Some still showed the
    window of v2.14.2.


tmDataQualityAnalyzer v3.0.0 - What's New
=================================

  The application has been rebuilt on a new user interface framework. It does
  the same jobs, in the same windows, and gives the same answers: every
  recording we hold was processed by both v2.14.2 and v3.0.0, in 34 runs
  covering every sample rate and averaging period, both stream modes,
  calibrations and batch runs, and every exported CSV file came out
  identical, byte for byte.

  What happens when you install it:

  - It replaces v2.x rather than installing beside it. Run the installer and
    it upgrades your existing installation in place: same folder, same Start
    menu entry, and the .ch10 file association moves to the new version.

  - Your settings files are kept. Frame sync patterns, receiver parameter
    files and calibration step files you saved or edited in the settings
    folder are never overwritten, exactly as before.

  - Your preferences come with you. The first time v3.0.0 starts, it reads
    the preferences v2.x kept - the theme, whether the log sidebar and the
    legend are shown, your recent files, and the folders you last opened
    recordings and calibration files from - and carries on from there.

  - If you need the previous version, v2.14.2 stays available for download
    from the project's releases page.

  New and improved:

  - Configure Streams says what is wrong as it happens. OK and Process wait
    until every stream you checked is ready, and a line under the list names
    the stream that is not. A stream whose Mode you change has to be set up
    again for its new mode, rather than keeping settings meant for the other.

  - Apply Cal is unavailable, with a tooltip saying why, when a calibration
    cannot be extracted (a setting has a problem, or the recording has no time
    channel), instead of warning you after the click.

  - The window's maximize button offers Windows 11's snap layouts.

  - Export picks the image format from the file name you give it (.png, .svg,
    or a PDF otherwise), and Browse adds the right extension for you.

  - In the legend, a Receiver SNR channel shown by its short name gives its
    full name as a tooltip.

  - The user manual has been rewritten for this version, with every figure
    taken from the application itself. The plain-text UserGuide.txt is gone:
    the manual replaces it, in the application under Help > User Manual and,
    if you choose, as the full illustrated manual installed beside it.

  Fixed:

  - Extract Calibration now uses the time channel you chose in Configure
    Streams and the recording's own byte order (Legacy Chapter 10). It used
    to take the recording's first time channel whatever you had chosen.

  - A batch run's exported images no longer draw the legend's rows on top of
    one another.

  - A recording stored under a folder whose name has accented or other
    non-English letters can now be processed. It could be opened and listed,
    but processing it failed.

  - A Receiver SNR stream given a sync mask that ignores some of the low 16
    bits no longer loses bits from its receiver values (and from the
    calibrations extracted from it).

  - A calibration sweep that saturates at the top, with a turn-on spike before
    it, is no longer numbered one step off.

  - A calibration report whose unnamed channels all calibrated lists them as
    calibrated, not under "Fell back to linear calibration".

  Good to know:

  - Processing very large recordings takes about 5% longer than v2.14.2. That
    is the cost of a Windows security protection (the hardware shadow stack)
    that this version runs with and v2.x did not.

  - The window now opens at 1920 x 1080.
